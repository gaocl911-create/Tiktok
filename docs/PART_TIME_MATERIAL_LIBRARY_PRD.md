## 1. 背景

当前兼职任务流程已经具备基础闭环：

```text
后台发布任务
-> 小程序用户领取任务
-> 用户自行发布抖音作品
-> 小程序提交作品链接
-> 后台审核
-> 审核通过后进入内容监测
```

但如果每个兼职人员都自己写文案、自己找图片，会出现以下问题：

- 内容质量不可控，容易偏离任务要求。
- 审核成本高，工作人员需要判断文案和图片是否符合预期。
- 同一任务下作品风格不统一，难以做效果对比。
- 后续如果增加 AI 生成，会扩大链路复杂度，不适合当前阶段。

因此本阶段将 AI 生成功能暂时移出小程序端，改为由后台工作人员维护“文案库”和“图片库”。任务发布时绑定素材分类，兼职人员领取任务后由系统自动按顺序分配文案和图片。

---

## 2. 目标

### 2.1 产品目标

建立一套后台可维护、小程序可领取、审核可追踪的任务素材分配机制。

核心目标：

1. 后台工作人员可以维护文案库、图片库和分类。
2. 发布兼职任务时可以选择文案分类和图片分类。
3. 用户领取任务后，系统自动分配一条文案和一张图片。
4. 分配结果固定保存，用户重复进入任务时看到相同素材。
5. 素材不够时按顺序循环分配，从头再来一轮。
6. 后台审核作品时可以看到该用户被分配的文案和图片。

### 2.2 业务收益

- 降低兼职人员创作门槛。
- 提高作品内容一致性。
- 降低审核成本。
- 方便后续统计不同文案和图片的效果。
- 为未来“小红书任务”“批量素材投放”“素材效果分析”预留结构。

---

## 3. 非目标

本期不做以下内容：

- 小程序端 AI 生成文案。
- 小程序端 AI 识图生成内容。
- 自动判断用户是否使用了指定文案。
- 自动判断用户是否使用了指定图片。
- 复杂素材推荐算法。
- 按用户画像智能分配素材。
- 素材 A/B 实验分析看板。
- 自动版权检测。

这些能力可以放到后续 P1/P2 阶段。

## 4. 用户角色

| 角色 | 使用场景 |
| --- | --- |
| 后台管理员 | 管理素材分类、维护文案和图片、创建任务、审核作品 |
| 兼职人员 | 在小程序领取任务，复制分配文案，保存分配图片，发布抖音作品 |
| 审核人员 | 在后台审核用户提交的作品，并查看该用户领取时分配的素材 |

## 5. 核心流程

### 5.1 后台维护素材

```text
进入素材库
-> 新建文案分类 / 图片分类
-> 添加文案 / 上传图片
-> 设置素材状态为启用
```

### 5.2 后台发布任务

```text
进入兼职任务管理
-> 新建任务
-> 填写任务标题、金额、要求、名额、截止时间
-> 选择文案分类
-> 选择图片分类
-> 发布任务
```

发布前校验：

- 文案分类必须存在至少 1 条启用文案。
- 图片分类必须存在至少 1 张启用图片。
- 任务发布后保存素材分类配置。

### 5.3 小程序领取任务

```text
用户进入任务广场
-> 点击领取任务
-> 后端创建领取记录
-> 后端根据领取顺序分配文案和图片
-> 小程序展示任务详情和分配素材
```

领取后用户可以：

- 一键复制文案。
- 查看或保存图片。
- 查看发布说明。
- 发布抖音作品后提交链接。

### 5.4 后台审核作品

```text
用户提交作品链接
-> 后台进入作品审核
-> 查看作品链接、用户信息、分配文案、分配图片
-> 审核通过 / 驳回
-> 审核通过后关联内容监测
```

## 6. 功能范围

### 6.1 后台：素材分类管理

支持两类分类：

- 文案分类
- 图片分类

字段建议：

| 字段 | 说明 |
| --- | --- |
| 分类名称 | 例如“冠心病推广文案”“冠心病推广图片” |
| 分类类型 | text / image |
| 排序 | 控制后台展示顺序 |
| 状态 | 启用 / 停用 |
| 备注 | 内部说明 |

规则：

- 已有关联任务的分类不建议硬删除，只能停用。
- 停用分类后，新任务不可选择。
- 已发布任务已绑定的分类不受分类停用直接影响，但领取时如果没有可用素材则不能领取。

### 6.2 后台：文案库

字段建议：

| 字段 | 说明 |
| --- | --- |
| 所属分类 | 文案分类 |
| 文案内容 | 发给用户复制的正文 |
| 排序 | 分配顺序依据 |
| 状态 | 启用 / 停用 |
| 使用次数 | 后续统计，可 P1 做 |
| 备注 | 内部说明 |

规则：

- 只有启用文案参与分配。
- 文案排序相同时按 ID 升序。
- 已分配过的文案不能硬删除，只能停用。
- 已分配记录需要保存文案快照，避免后续修改影响历史任务。

### 6.3 后台：图片库

字段建议：

| 字段 | 说明 |
| --- | --- |
| 所属分类 | 图片分类 |
| 图片地址 | MinIO 或其他文件存储地址 |
| 图片名称 | 后台展示 |
| 排序 | 分配顺序依据 |
| 状态 | 启用 / 停用 |
| 使用次数 | 后续统计，可 P1 做 |
| 备注 | 内部说明 |

规则：

- 只有启用图片参与分配。
- 图片排序相同时按 ID 升序。
- 已分配过的图片不能硬删除，只能停用。
- 已分配记录需要保存图片地址快照，避免后续修改影响历史任务。

### 6.4 后台：任务发布绑定素材分类

兼职任务新增配置：

| 字段 | 说明 |
| --- | --- |
| 文案分类 | 当前任务领取时使用哪个文案库 |
| 图片分类 | 当前任务领取时使用哪个图片库 |
| 素材分配方式 | 本期固定为“顺序循环分配” |

规则：

- 发布任务时必须选择文案分类和图片分类。
- 分类内没有启用素材时不允许发布。
- 草稿状态可以修改分类。
- 已发布任务是否允许修改分类需要谨慎处理。

建议本期规则：

- 已发布任务允许修改分类，但只影响后续新领取用户。
- 已领取用户的素材分配不受影响。
- 修改分类需要记录操作日志。

### 6.5 小程序：任务详情展示素材

任务领取后展示：

- 任务标题
- 任务要求
- 任务金额
- 截止时间
- 分配文案
- 复制文案按钮
- 分配图片
- 保存图片按钮
- 提交作品入口

未领取前不展示具体素材，只展示任务要求和领取按钮。

### 6.6 后台：作品审核展示素材

作品审核列表和详情需要展示：

- 用户提交作品链接
- 用户提交作品文案
- 系统分配文案
- 系统分配图片
- 领取时间
- 提交时间
- 审核状态

审核人员可以用这些信息判断用户是否按任务素材发布。

## 7. 分配规则

### 7.1 核心规则

用户领取任务时，系统为领取记录分配一个稳定的领取序号 `assign_index`。

文案和图片独立循环分配：

```text
text_index = (assign_index - 1) % enabled_text_count
image_index = (assign_index - 1) % enabled_image_count
```

示例：

文案 3 条，图片 5 张。

| 领取序号 | 文案 | 图片 |
| ---: | --- | --- |
| 1 | 文案1 | 图片1 |
| 2 | 文案2 | 图片2 |
| 3 | 文案3 | 图片3 |
| 4 | 文案1 | 图片4 |
| 5 | 文案2 | 图片5 |
| 6 | 文案3 | 图片1 |

### 7.2 固定分配

领取成功后必须保存分配记录：

- claim_id
- task_id
- user_id
- assign_index
- text_id
- text_snapshot
- image_id
- image_url_snapshot

用户刷新页面、重新进入任务、提交作品时，都读取这条分配记录。

### 7.3 并发规则

领取任务时可能有多个用户同时点击领取。后端必须保证：

- 同一个用户不能重复领取同一个任务。
- 同一个领取记录只能生成一条素材分配。
- `assign_index` 不能因为并发出现重复或跳乱导致不可追踪。

建议实现方式：

- 领取任务和素材分配放在同一个数据库事务中。
- 对任务领取计数或任务行加锁。
- 对 `task_id + user_id` 建唯一约束。
- 对 `claim_id` 建唯一分配约束。

## 10. 异常场景

| 场景 | 处理方式 |
| --- | --- |
| 分类为空 | 不允许发布任务 |
| 任务已发布后素材全部停用 | 新用户领取时提示“任务素材暂不可用”，后台需要处理 |
| 用户重复领取 | 返回已有领取记录和已有分配素材 |
| 用户领取成功但分配失败 | 整个事务回滚，不能留下半条领取记录 |
| 素材被修改 | 已分配用户继续使用快照 |
| 素材被删除 | 已分配历史不受影响，未分配不再使用 |
| 图片保存失败 | 小程序提示用户长按保存或重试 |
| 提交作品时无分配记录 | 阻止提交，并提示重新进入任务详情 |

## 11. 验收标准

### 11.1 后台验收

- 可以新增、编辑、停用文案分类。
- 可以新增、编辑、停用图片分类。
- 可以新增、编辑、停用文案。
- 可以上传、编辑、停用图片。
- 创建任务时可以选择文案分类和图片分类。
- 分类没有启用素材时不能发布任务。
- 作品审核页可以看到用户分配到的文案和图片。

### 11.2 小程序验收

- 未领取任务前不展示具体文案和图片。
- 领取成功后展示固定文案和固定图片。
- 重复进入任务详情，文案和图片不变化。
- 文案可以一键复制。
- 图片可以查看并保存。
- 提交作品时和领取记录关联正确。

### 11.3 分配规则验收

- 文案按排序顺序循环分配。
- 图片按排序顺序循环分配。
- 文案数量和图片数量不一致时可以独立循环。
- 多个用户领取时不会重复创建领取记录。
- 同一用户重复点击领取不会重复分配素材。

- 自动识别作品是否使用指定文案或图片。

## 13. 当前决策

本期采用以下决策：

1. 小程序端不做 AI 生成功能。
2. 后台工作人员负责上传文案和图片。
3. 任务发布时绑定文案分类和图片分类。
4. 用户领取任务时自动分配素材。
5. 分配方式为顺序循环。
6. 分配结果固定保存。
7. 审核页展示分配素材。
8. 已分配素材保留快照，避免后续修改影响历史数据。
