## 1. 计划目标

在现有抖音作者、作品和监控能力之上，完成以下业务闭环：

```text
兼职入驻
→ 管理员发布任务
→ 兼职领取任务
→ 获取要求和素材
→ 发布并提交抖音作品
→ 系统识别和监控作品
→ 后台审核
→ 生成佣金
→ 财务人工结算
→ 兼职查看结算结果
```

第一版完成标准不是页面数量，而是至少5名真实测试兼职可以完整走通上述流程。

## 2. 当前项目基础

### 2.1 已具备能力

- 若依管理后台、用户、角色、部门和菜单权限。
- 管理员、本人、部门及递归下级数据权限。
- 抖音作者识别和作者监控。
- 抖音单作品链接识别。
- 作品作者、文案、封面和互动指标展示。
- 单作品监控目标和指标快照。
- 作品详情及24小时、7天、30天趋势。
- SnailJob真实调度和到期监控目标采集。
- 预警事件和采集运行记录。

### 2.2 可以直接复用

兼职提交作品时直接复用：

```text
TikHubDouyinClient
→ 作品链接提取
→ 作者和作品入库
→ single_content监控目标
→ 首次指标快照
→ SnailJob持续采集
```

禁止为小程序重新开发另一套抖音识别和采集逻辑。

### 2.3 尚未实现

- `miniapp`目前为空工程。
- 兼职业务扩展资料和入驻审核。
- 任务、领取、提交和审核数据表。
- 后台任务管理和审核中心。
- 小程序登录、任务广场、我的任务和提交作品。
- 佣金台账、调整记录和结算批次。
- 兼职业务通知。

## 3. 一期范围

### 3.1 MVP必须实现

- 微信登录和手机号绑定。
- 兼职资料填写及人工审核。
- 后台创建、发布、暂停和结束任务。
- 固定任务单价、名额和有效期。
- 任务要求和基础附件。
- 兼职领取任务。
- 兼职提交抖音作品链接。
- 作者归属、发布时间和重复作品校验。
- 后台一级审核和驳回原因。
- 审核通过后生成固定佣金。
- 财务人工确认线下结算。
- 兼职查看本人任务、作品、佣金和结算记录。

### 3.2 MVP暂不实现

- AI自动生成文案。
- 多级审核。
- 阶梯佣金、自动奖励和自动扣款。
- 自动微信、银行卡打款和提现。
- 多级代理和复杂邀请分佣。
- 小红书任务。
- 智能风控和作品内容AI审核。
- 独立App。

这些功能放到真实兼职闭环稳定之后，避免扩大一期风险。

## 5. PT-0：规则与原型冻结

### 5.1 必须确认的规则

1. 兼职入驻是否必须人工审核。建议：必须审核。
2. 一个兼职是否可多次领取同一任务。建议：一期默认不可。
3. 是否允许同一作者参加同一任务多次。建议：默认不可。
4. 是否允许同一作品提交到多个任务。建议：默认不可。
5. 领取后多久必须提交。建议：不晚于任务截止时间。
6. 驳回后是否允许重新提交。建议：允许，且保留历史记录。
7. 是否必须使用已绑定抖音账号。建议：任务可配置，一期默认必须。
8. 审核通过后的作品需要监控多久。建议：默认30天。
9. 任务单价修改是否影响已领取人员。规则：不影响，领取时保存快照。
10. 结算周期。建议：每周或每半月人工结算。

### 5.2 状态机

任务：

```text
draft → published → paused → published
                  → finished → archived
                  → cancelled
```

领取和提交：

```text
claimed → submitted → approved → settled
                    → rejected → submitted
claimed → expired
claimed → cancelled
```

兼职入驻：

```text
incomplete → pending → approved
                    → rejected → pending
approved → disabled
```

### 5.3 UI原型范围

后台：

- 任务列表。
- 创建/编辑任务。
- 任务详情。
- 提交审核中心。
- 兼职人员与入驻审核。
- 佣金台账。
- 结算批次。

小程序：

- 登录和资料完善。
- 首页。
- 任务广场。
- 任务详情。
- 我的任务。
- 提交作品。
- 我的作品。
- 我的佣金。
- 个人中心。

### 5.4 验收标准

- 所有规则形成明确选项，不使用“后面再看”的模糊描述。
- 任务、领取、提交、审核、佣金状态不存在循环歧义。
- 管理后台和小程序核心页面线框确认。

## 6. PT-1：数据模型与后端骨架

### 6.1 数据表

建议新增：

```text
pt_staff_profile          兼职业务资料
pt_promotion_task         推广任务
pt_task_claim             任务领取
pt_task_submission        作品提交
pt_task_audit_record      审核记录
pt_material_asset         素材文件
pt_task_material          任务素材关系
pt_commission_ledger      佣金台账
pt_commission_adjustment  佣金调整记录
pt_settlement_batch       结算批次
pt_settlement_item        结算明细
```

### 6.2 关键唯一约束

- 兼职用户业务资料：`tenant_id + user_id`唯一。
- 默认任务领取：`tenant_id + task_id + user_id`唯一。
- 任务作品提交：`tenant_id + task_id + content_id`唯一。
- 佣金来源：`tenant_id + submission_id`唯一。
- 结算明细：`tenant_id + settlement_batch_id + commission_id`唯一。
- 微信身份：`tenant_id + open_id`唯一。

### 6.3 后端模块

继续放在`ruoyi-creator`业务模块内，按包隔离：

```text
org.dromara.creator.parttime
├─ controller
├─ domain
├─ mapper
├─ service
└─ enums
```

达到独立部署需求前不新增微服务。

### 6.4 后台基础接口

```text
GET    /parttime/task/list
GET    /parttime/task/{id}
POST   /parttime/task
PUT    /parttime/task
POST   /parttime/task/{id}/publish
POST   /parttime/task/{id}/pause
POST   /parttime/task/{id}/finish

GET    /parttime/staff/list
GET    /parttime/staff/{id}
POST   /parttime/staff/{id}/approve
POST   /parttime/staff/{id}/reject
POST   /parttime/staff/{id}/disable
```

### 6.5 测试重点

- 唯一约束和幂等。
- 租户隔离。
- 上级递归查看下属兼职数据。
- 删除任务不物理删除已领取和提交记录。
- 金额统一使用`decimal`，禁止浮点数。

### 6.6 验收标准

- 数据库脚本可以重复执行。
- 基础增删改查接口通过测试。
- 普通兼职无法访问后台管理接口。
- 管理员和直属上级的数据范围正确。

## 7. PT-2：后台任务管理

### 7.1 页面

```text
web/src/views/parttime/
├─ task/index.vue
├─ task/form.vue
├─ task/detail.vue
├─ staff/index.vue
├─ staff/detail.vue
└─ material/index.vue
```

### 7.2 任务列表

展示：

- 任务名称和编号。
- 平台、单价和有效期。
- 总名额、已领取、已提交和已通过。
- 所属部门和负责人。
- 任务状态。
- 预计佣金。

支持创建、编辑、发布、暂停、结束、复制和查看详情。

### 7.3 创建任务

使用五步表单：

```text
基本信息 → 发布要求 → 素材附件 → 名额佣金 → 预览发布
```

长表单自动保存草稿，发布前执行完整校验。

### 7.4 素材能力

MVP只实现：

- 图片、视频和文档上传。
- 任务关联素材。
- 有效期。
- 小程序授权下载。

不实现复杂分类、在线编辑和素材版本协作。

### 7.5 验收标准

- 管理员能创建一条真实任务并发布。
- 发布后的关键规则不可直接覆盖已领取快照。
- 暂停任务后新用户不能领取，已领取用户仍能查看。
- 任务统计数与领取、提交数据一致。

## 9. PT-4：任务领取与作品提交

### 9.1 小程序页面

- 首页任务摘要。
- 任务广场。
- 任务详情。
- 我的任务。
- 提交作品。
- 识别结果确认。

### 9.2 领取接口

```text
GET  /miniapp/task/list
GET  /miniapp/task/{id}
POST /miniapp/task/{id}/claim
GET  /miniapp/task/my
```

领取必须在事务内完成：

1. 锁定任务记录。
2. 校验任务状态和有效期。
3. 校验兼职状态。
4. 校验重复领取和个人上限。
5. 校验剩余名额。
6. 创建领取记录。
7. 保存任务规则和单价快照。
8. 更新已领取数量。

### 9.3 作品提交

```text
POST /miniapp/task/claim/{claimId}/preview-content
POST /miniapp/task/claim/{claimId}/submit-content
GET  /miniapp/submission/{id}
```

预览阶段：

- 提取抖音链接。
- 识别作品、作者、文案和发布时间。
- 展示给兼职人员确认。

确认提交阶段：

- 校验任务未过期。
- 校验作者归属。
- 校验发布时间。
- 校验作品和作者是否重复。
- 创建或复用`cm_creator_account`。
- 创建或复用`cm_content_post`。
- 创建`single_content`监控目标。
- 创建任务提交记录。
- 触发首次采集。
- 进入待审核。

### 9.4 异常提示

必须给出明确原因：

- 链接无法识别。
- 不是本人绑定账号。
- 作品发布时间不符合要求。
- 该作品已提交。
- 任务已过期。
- 名额已满。
- TikHub暂时不可用，可稍后重试。

### 9.5 验收标准

- 并发领取不会超发名额。
- 重复点击领取不会生成重复记录。
- 提交后可以在现有内容监测中看到作品。
- 任务作品只建立单作品监控，不扩展作者历史作品。
- TikHub失败不会产生半条提交或错误佣金。

## 10. PT-5：审核中心与作品监控

### 10.1 后台页面

```text
web/src/views/parttime/audit/index.vue
```

采用左侧待审核列表、右侧作品详情的双栏结构。

### 10.2 审核信息

- 兼职资料和绑定抖音账号。
- 任务要求和领取快照。
- 作品封面、作者、文案和发布时间。
- 最新点赞、评论、收藏和分享。
- 作者归属校验结果。
- 发布时间校验结果。
- 重复作品校验结果。
- 历史审核记录。

### 10.3 审核动作

```text
POST /parttime/submission/{id}/approve
POST /parttime/submission/{id}/reject
POST /parttime/submission/{id}/request-supplement
```

审核通过必须在一个事务中：

1. 锁定提交记录。
2. 校验仍为待审核状态。
3. 修改为审核通过。
4. 写入审核记录。
5. 生成唯一佣金台账。
6. 保持作品持续监控。

### 10.4 驳回规则

- 必须填写驳回原因。
- 不生成佣金。
- 允许重新提交时保留原提交和审核记录。
- 默认暂停被驳回作品的高频采集。

### 10.5 验收标准

- 重复点击审核通过不会重复生成佣金。
- 无审核权限用户不能审核。
- 兼职只能查看自己的审核结果。
- 审核记录不可被普通编辑覆盖。

## 11. PT-6：佣金与人工结算

### 11.1 后台页面

```text
web/src/views/parttime/
├─ commission/index.vue
├─ settlement/index.vue
└─ settlement/detail.vue
```

### 11.2 佣金规则

一期公式：

```text
应付金额 = 领取时单价快照 + 人工奖励 - 人工扣减
```

调整必须记录调整前金额、调整后金额、原因、操作人和时间。

### 11.3 结算流程

```text
筛选待结算佣金
→ 创建结算批次
→ 核对人数、作品数和金额
→ 线下微信/银行卡付款
→ 上传支付凭证
→ 确认已结算
→ 小程序显示结果
```

### 11.4 接口

```text
GET  /parttime/commission/list
POST /parttime/commission/{id}/adjust
POST /parttime/settlement
GET  /parttime/settlement/list
GET  /parttime/settlement/{id}
POST /parttime/settlement/{id}/confirm

GET  /miniapp/commission/summary
GET  /miniapp/commission/list
GET  /miniapp/settlement/list
```

### 11.5 验收标准

- 一个审核提交只能生成一条佣金。
- 结算批次总额等于明细金额之和。
- 同一个结算批次重复确认不会重复改变账目。
- 已结算佣金不能再次进入其他批次。
- 兼职只能查看本人佣金。

## 12. PT-7：联调、试运营与上线

### 12.1 自动化和回归测试

- 任务名额并发领取。
- 重复领取。
- 任务暂停、结束和过期。
- 非本人作品提交。
- 同一作品重复提交。
- TikHub识别超时和失败。
- 重复审核。
- 重复生成佣金。
- 重复结算确认。
- 直属上级递归数据权限。
- 租户隔离。
- 素材越权下载。

### 12.2 试运营

准备：

- 1名管理员。
- 1名审核人员。
- 1名财务人员。
- 至少5名测试兼职。
- 2至3个真实抖音任务。
- 每个任务5至10个测试名额。

每名兼职至少完成：

```text
登录
→ 入驻审核
→ 领取任务
→ 下载素材
→ 发布抖音作品
→ 提交链接
→ 查看审核结果
→ 查看佣金
→ 查看结算
```

### 12.3 运行监控

- SnailJob任务成功率。
- TikHub调用次数、失败率和费用。
- 待审核积压数量。
- 任务名额异常。
- 待结算金额。
- 登录和作品提交接口错误率。

### 12.4 上线门槛

- 无名额超发。
- 无重复佣金。
- 无重复结算。
- 无跨用户、跨部门或跨租户数据泄露。
- 真实作品识别和监控成功率达到业务可接受水平。
- 关键失败场景有明确提示和恢复路径。
- 数据库已备份，回滚脚本已演练。

### 13.2 第一批开发任务

3. 创建兼职业务后端包、实体、Mapper和权限标识。
4. 完成后台任务列表和创建任务。
5. 完成任务发布、暂停和结束。
